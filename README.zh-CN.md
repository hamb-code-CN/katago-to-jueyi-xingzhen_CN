# 围棋 AI 自动对局系统（GoAI Auto-Player）

一个**纯视觉闭环**的围棋自动下棋机器人：不读取任何棋软内部数据、不注入进程、不调私有接口，
只靠"看屏幕"完成全部操作 —— **截图 → 棋盘识别 → KataGo 决策 → 模拟点击 → 再次截图核对**，
因此对任何能显示棋盘的围棋客户端都通用。

当前已适配两个平台：

| 平台 | 类型 | 轮次识别方式 |
|---|---|---|
| 腾讯围棋 | Windows 原生客户端 | 顶部红章 OCR（"黑方行棋/白方行棋"） |
| 星阵围棋（19x19.com / Galaxy） | Edge/Chrome 网页 | 头像蓝水滴 HSV 检测（<10ms，免 OCR） |

## 功能一览

-  **KataGo 决策**：本地常驻服务预加载，每手免冷启动；KataGo 不可用时自动回退内置轻量引擎
-  **棋力强**：默认权重即可轻松战胜星阵三星、绝艺九段等在线顶级 AI（受平台限时，由你设定每手思考时间决定深度）
-  **拟人节奏**：每手思考时间随机化（防 AI 特征）；中盘（≥60 手）胜率 <30% 时自动延长思考（最多 20s）
-  **打劫（ko）处理**：逐帧跟踪真实落子历史并同步给 KataGo，劫争中主动找劫材；本地二次合法性校验拦截非法回提
-  **非法点自动顺延**：候选点已占/劫/禁手时，自动改下 KataGo 本次搜索的**次优着法**，绝不反复重试同一非法点（无死循环）
-  **中途加入也能准确分析**：无完整落子历史时，用 KataGo 原生 `set_position` 快照摆盘，盘面与真实 100% 一致（仅缺接入瞬间的劫，会安全顺延），无需从开局监视
-  **实时看板**（http://127.0.0.1:8123/analysis.html）：
  - 棋盘标注图：AI 推荐候选点、最佳点、坐标轴
  - 候选点列表（传统中文坐标）—— 显示**落子后 AI 胜率**（按 AI 执子颜色自动换算）
  - **AI 胜率走势曲线图**（随对局推进，自动重置）
  - 网页版启动器：启动/停止/重开一局(进程不重启)/智力档位/对手软件切换/导出棋谱/通知设置
  - 局域网/手机可访问（IPv4 + IPv6 双栈）
-  **双平台自适应**：窗口拖动、缩放、最小化（腾讯走 PrintWindow）均能定位
-  **终局识别与自动收尾**（v1.0.3）：引擎认输 / 连续虚着 / 盘面长时间静止（且界面已无行棋印章）任一命中即判终局 → **自动导出 SGF 棋谱 + 发通知 + 停止 AI**，不用人盯着
-  **SGF 棋谱导出**（v1.0.3）：按真实落子顺序导出，可直接用其他 SGF 软件复盘；看板一键导出，或终局自动导出到 `go_ai/games/`
-  **事件通知**（v1.0.3，默认关闭）：对局结束 / 引擎掉线 / 思考出错时，向自定义 URL POST 一条 JSON（可接自己的机器人、群机器人等）
-  **数字棋盘看板**（v1.0.3）：前端用 Canvas **自己画棋盘**（木纹底、渐变棋子、中国坐标、候选点带胜率标签、最后一手红点），不再依赖截图拼接，比实拍图干净得多；顶栏可一键切回「实拍」对照
-  **后台识别（v1.0.3）**：读盘默认走 **PrintWindow 直接抓窗口内容**，围棋窗口被别的程序盖住、甚至最小化都能识别，不必一直把棋盘摆在前台（`capture.mode` 可切 auto/window/screen；镜像方向可在看板里一键切换）
-  **双重自愈**（v1.0.3）：① KataGo 服务内置看门狗，引擎进程崩溃后自动重建；② 看板看门狗在 controller 异常退出后自动拉起（主动停止与终局退出不会误触发）
-  **识别阈值自适应**（v1.0.3）：黑/白判据由木色采样自动推导，换主题、换显示器、改系统缩放不必再手改代码
-  **配置单一真源**（v1.0.3）：全部参数集中在 `go_ai/settings.json`，命令行 > 配置文件 > 内置缺省，不再出现"改了没生效"
-  **辅助模式：AI 不出手，你点选落子**（v1.0.3）：看板「落子方式」选 **辅助模式** 后，AI **只给胜率与候选点**，落哪里由你决定 —— 直接**点棋盘交点**、或**点候选行**，它就在客户端帮你落子。玩家点选同样过合法性校验（已有子 / 劫 / 自杀 / 禁手都会被拦下并说明原因），不会把客户端点乱。另有 **仅分析** 模式（纯围观，永不出手）
-  **单实例保护**（v1.0.3）：单机只允许一个 AI 占棋盘，并修复了看门狗在进程枚举失效时"每 30 秒拉一个"的僵尸风暴
-  **回归测试**（v1.0.3）：114 个用例（规则/劫/识别/配置/SGF/终局判定/单例锁/辅助模式/主循环冒烟），一条命令跑完，CI 每次提交自动跑

## 模型下载与加载（重要）

### 下载

KataGo 网络权重（`.bin.gz` 格式）来自 KataGo 官方项目（出处与许可见 ACKNOWLEDGMENTS.md）：

- **GitHub Releases（推荐）**：https://github.com/lightvector/KataGo/releases
  在 Assets 中找 `.bin.gz` 权重文件，例如 `kata1-b18c384nbt-s9996604416-d4316597426.bin.gz`
  （文件名含义：`b18c384` = 18 层 / 384 通道；`b28c512` 等为更强更大的型号）
- 本项目随附（非开源仓库场景）的默认权重即为 **b18c384nbt**，下载同规格即可

> 想要更强？选 `b28c512` / `b30` 等更大权重即可，但需要更强的显卡（前馈更慢），
> 并建议同步使用 KataGo 最新版引擎（见"换更强模型"）。

### 放置

把下载好的 `.bin.gz` 放进 **`katago\`** 根目录即可，**文件名随意**。代码按以下优先级自动加载：

1. **环境变量 `GOAI_KATAGO_MODEL`** —— 最高优先级（绝对路径，或相对 katago 根的文件名）
2. **目录自动发现** —— 若 `katago\` 下恰好只有一个 `*.bin.gz`，自动采用（推荐：删掉旧的、只留一个新的）
3. **默认文件名** —— `katago\kata-b18c384nbt.bin.gz`

放置后需**重启常驻服务**使其生效：看板启动器面板 → 「KataGo 引擎预加载」→「启动 / 重启预加载」（或重启整个 AI）。

### 换更强模型

1. 下载新权重 → 放入 `katago\`（删旧，或设 `GOAI_KATAGO_MODEL` 指定）
2. 若新权重来自新版本 KataGo，同步替换 `katago\opencl171\katago.exe`（旧引擎可能读不了新格式模型）
3. 重启预加载服务
4. 大模型单次推理更慢 → 在看板把「智力档位」调高一档（更多思考时间），保持搜索深度

## 高级配置（settings.json）

全部参数集中在 `go_ai/settings.json`，改完**下次启动 AI 生效**（看板里能改的会立即写回该文件）。
首次运行会自动把旧的 `launcher_config.json` 迁移过来（旧文件保留，可自行删除）。

常用片段：

```jsonc
{
  "level": "中级",              // 智力档位；手动改 tmin/tmax 会变成"自定义"
  "katago": {
    "playout_doubling_advantage": 0.0,   // >0 让 AI 变弱（放水档），0 = 全强度
    "num_search_threads": 0              // 0 = 交给引擎按 CPU 自适应
  },
  "weights": {                  // 中盘低胜率延长思考（enabled=false 可关闭）
    "enabled": true, "min_moves": 60, "winrate": 0.30, "max_time": 20.0
  },
  "auto_stop": {                // 终局识别与收尾
    "enabled": true,            // 判到终局自动停止 AI
    "stable_cycles": 12,        // 盘面连续多少轮不变 (+无行棋迹象) 算终局
    "export_sgf": true          // 终局自动导出棋谱
  },
  "notify": {                   // 事件通知（默认关闭）
    "enabled": false,
    "url": "",                  // 任意接收 JSON POST 的地址
    "events": ["terminal", "engine_down", "error"]
  },
  "sgf": { "dir": "" },         // 棋谱目录，空 = go_ai/games/
  "watchdog": {                 // controller 异常退出后自动拉起
    "auto_restart": true, "max_restarts": 5
  },
  "capture": {                  // 取图方式（后台识别的关键）
    "mode": "auto",             // auto=先窗口后全屏 | window=只用窗口(可后台) | screen=只用全屏
    "mirror": "auto"            // 窗口图是否水平翻转; 数字棋盘左右反了就改成 "off"
  },
  "dashboard": {
    "board_view": "digital"     // digital=前端画棋盘(推荐) | photo=实拍截图
  }
}
```

**通知怎么接**：填一个能收 `POST` JSON 的地址即可（自建服务、群机器人网关等都行），载荷形如
`{"event":"terminal","title":"对局结束 · 引擎认输","text":"共 213 手; AI胜率 62.3%","time":"..."}`。
填完点看板里的「发测试通知」验证连通性，日志见 `go_ai/notify.log`。

**棋谱在哪**：终局自动导出到 `go_ai/games/`（文件名 `game_YYYYmmdd_HHMMSS.sgf`），
也可以随时点看板「导出当前棋谱」。有完整落子历史时导出的是**带手数顺序**的棋谱，可直接复盘。

## 常见问题

**Q：一局下完，AI 会自己停吗？**
A：会（v1.0.3 起）。识别到终局（引擎认输 / 连续虚着 / 盘面长时间静止且界面已无行棋印章）后，
会自动导出棋谱、发通知、停止 controller。看板「启动器 → 棋谱 / 终局」里能看到上一局结果。
不想要这个行为就把 `settings.json → auto_stop.enabled` 改成 `false`（或启动时加 `--no-auto-stop`）。

**Q：对局还没结束，AI 怎么就判终局停了？**
A：说明"盘面静止 + 界面识别不到行棋方"同时成立了很久。把 `auto_stop.stable_cycles` 从 12 调大
（比如 30，配合 5s 轮询 ≈ 2.5 分钟）即可；也可以只关自动停止、保留棋谱导出。

**Q：KataGo 进程崩了要手动重启服务吗？**
A：不用（v1.0.3 起）。`kata_service.py` 内置看门狗，每 10s 检查一次，进程没了会自动重建；
重建失败会退避 30s 再试。状态见看板「运行状态」与 `go_ai/kata_service.log`。

**Q：换了显示器 / 改了系统缩放 / 换了棋盘主题，识别会不会不准？**
A：v1.0.3 起黑白判据是按盘面木色采样**自动推导**的，一般不用改代码。若仍识别异常：
先用 `--debug` 跑一轮，把 `go_ai/debug/cycle_xxx_dbg.png` 打开看标定是否对得上；
印章轮次识别也已改为自动定位，不再依赖固定像素坐标。

**Q：通知配置好了但收不到？**
A：先点看板里的「发测试通知」，然后看 `go_ai/notify.log`：里面会写 `OK <event> -> <url> <状态码>`
或 `FAIL ... <错误>`。注意默认 `notify.enabled=false`，只填 URL 不勾启用是不会发的。

**Q：启动后提示找不到模型 / KataGo 不可用？**
A：模型未放入 `katago\`。下载 `.bin.gz` 放进去 → 重启预加载服务。模型缺失时系统会自动回退到本地轻量引擎（棋力弱，仅兜底）。

**Q：AI 卡在"对方行棋 / 非我方回合"不动？**
A：确认围棋客户端窗口在前台可见、已开始对局、看板选对了「对手软件」平台。

**Q：AI 中途加入（非空盘）一局能正常下吗？**
A：能。无完整落子历史时引擎自动改用 `set_position` 快照摆盘，盘面与真实完全一致；仅当加入瞬间恰好正打劫时，那一手缺劫点（会安全顺延到次优点，不卡死），之后完全正常。**从新局开局则劫处理最完整**。

**Q：为什么偶尔看到"历史不一致, 清空重来"日志？**
A：多帧之间棋盘识别抖动导致的正常降级提示（历史被清空后改用快照摆盘继续），不影响对局推进。

**Q：换模型后棋力没提升？**
A：先确认新模型已生效（重启服务后日志显示加载的模型路径）；并调高思考档位给足搜索时间。

## 原理简介

```
每个循环:
  ① 处理网页指令(_command.json)   重置/换色, 不重启进程
  ② 截图 → 检测棋盘(木色HSV+19线网格拟合) → 读 361 交点(空/黑/白)
  ③ 判轮次: 腾讯=红章OCR · 星阵=头像水滴 · 兜底=子数法
  ④ 轮到我方 → KataGo genmove(随机思考时长, 劣势自动延长)
  ⑤ 合法性校验(含劫): 最佳点非法 → 自动顺延本次搜索次优候选落子; 候选耗尽才放弃本轮
  ⑥ 点击落子 → 等动画 → 再次截图核对"我方子数+1"才收手
```

完整架构与数据流：见 `go_ai/GO_AI_ARCHITECTURE.md`

## 更新日志

### v1.0.3（2026-09-12）

**新增能力**

- **终局识别 + 自动收尾**：三个独立信号（引擎认输 / 我方连续虚着 / 盘面连续 N 轮静止且界面已无"行棋"印章）任一命中即判终局；自动导出 SGF、发通知、停止 AI。判定带"旁证"条件，不会把对手长考误判成终局。
- **SGF 棋谱导出**：按真实落子顺序导出（无历史时退化为摆盘），看板一键导出，终局自动保存到 `go_ai/games/`，并写入 `game_result.json` 供看板显示上一局结果。
- **事件通知**（默认关闭）：`settings.json → notify` 里填一个 URL 即可，对局结束 / 引擎掉线 / 思考出错时 POST JSON。
- **KataGo 服务引擎自愈**：新增健康检查线程，KataGo 进程崩溃（OOM / 显卡驱动重启等）后自动重建引擎并继续服务 —— 以前只在启动时建一次，进程一死服务就永久失效。
- **看板 controller 看门狗**：controller 异常退出后自动拉起；主动"停止"（120s 冷却）与终局自动退出（10 分钟内结果文件）不会误触发；连续重启超过上限会停下，避免崩溃循环。
- **识别阈值自适应**：黑子灰度 / 白子饱和度阈值改由交点木色采样自动推导（现网行为与旧经验值 150/80 一致），换主题、换显示器、改系统缩放后不必改代码。印章轮次识别也不再写死 `y150:260 / mid_x=391`，改为自动定位印章高度带 + 画面中线分左右。
- **放水档 / 线程数可配**：`settings.json → katago.playout_doubling_advantage`（>0 让 AI 变弱）、`num_search_threads`。
- **配置单一真源**：全部参数集中到 `go_ai/settings.json`（首次运行自动从 `launcher_config.json` 迁移，旧文件保留）；命令行 > 配置文件 > 内置缺省。
- **中盘延长思考可配**：原 `WEIGHT_*` 硬编码常量改为 `settings.json → weights`（可关闭）。

**界面**

- **看板改为白色 + 米色浅色主题**（宣纸质感）：顶栏白色带木色细描边、棋盘区米色渐变衬底、
  卡片圆角加暖色柔阴影；候选点榜首用米金色渐变高亮，走势图改用木色/暖灰配色
  （原来深色主题下"白方曲线是纯白"在浅色背景上看不见，已换成暖灰并加描边）。
  冷启动闸门卡片同步改为白卡 + 米色进度条。
- **数字棋盘（前端自绘）**：棋盘由 Canvas 直接绘制 —— 木纹底 + 径向渐变棋子（带投影）、
  传统中文坐标、星位、**最后一手红点**、候选点圆环按胜率着色并带胶囊胜率标签。
  不再需要把截图拼成棋盘图，省带宽也更清楚；顶栏「数字棋盘 / 实拍」可随时切换（选择记在本地）。
  后端在 `data.json` 里新增 `stones`（19×19 盘面）、`last_move`、`capture` 字段。

**稳定性 / 性能**

- **后台识别**：读盘默认改用 **PrintWindow 抓窗口内容**（`go_vision.grab_for_read()`），
  窗口被遮挡/最小化也能识别，不再依赖前台全屏截图；窗口取不到时自动回落到全屏截图。
  新增 `capture.mode`（auto/window/screen）与 `capture.mirror`（auto/on/off）；

  ⚠️ 自动落子仍需要窗口在前台（点击是模拟鼠标），后台取图主要让**看板/识别**不受遮挡影响。

- **GTP 读取层重写**：每发一条命令起临时线程 `readline()`、超时线程塞进 `_pending` 逐个 join（最长 45s）的旧机制，改为**常驻读线程 + 队列**，超时响应按条数在下次发送前丢弃。竞态从设计上消失，超时不再污染后续命令。
- **读子阈值/终局判定等纯逻辑抽离**（`game_state.py`），可在无显示器环境单测。
- **兜底引擎清理与提速**：删掉 `play()` 里的空操作分支与 `final_score()` 死代码；选点加邻域剪枝（不再对全部 361 点做完整启发评估），蒙特卡洛过程改为增量维护空点表。

**工程化**

- **回归测试**：114 个用例（规则/提子/劫/自杀、SGF、配置校验、通知、终局状态机、单例锁、辅助模式、合成棋盘识别、主循环冒烟），标准库 `unittest`，不需要额外依赖：
  ```
  cd go_ai && python -m unittest discover -s tests -v
  ```
- **GitHub Actions**：`.github/workflows/ci.yml` 每次提交自动跑语法检查 + 测试 + 打包自检；`release.yml` 打 tag 即发版（跑测试 → 打包 → 生成 SHA256 → 创建 Release）。
- **打包脚本化**：`python tools/make_release.py [--with-model]`，只打 git 跟踪的文件，不再把 venv / 调试日志 / 识别缓存打进包里。
- **依赖锁定**：`requirements.txt` 改为精确版本（另附 `requirements-flexible.txt` 供新机器搭环境）。
- **代码清洁**：清掉 `go_engine` 死代码、`go_controller` 未使用的导入（`detect_turn_side` / `snap_to_cal` / `capture_go_window`）。

**修复**

- **「最后一手」红标被读成空点，导致 AI 死循环（严重）**：部分客户端会在最后一手上画一个朱砂红方块。它盖住棋子中心后，棋子邻域的平均颜色被拉红（白子饱和度从 0.10 涨到 0.35），被误判成**空点**；引擎于是在"空盘面"上认为该点是最佳点，反复点击一个已被占据的点 —— 客户端拒绝，子数不变，下一轮又读到同样的"空点"。实测连续 115 轮空转，一次都没落成。
  - 根因修复：读子前**剔除朱砂红标记像素**（`go_vision.marker_red_mask`），再统计黑白；剔除过多时保守退回整块统计。实测该点从"空点"恢复成白子，盘面计数正确。
  - 双保险：同一交点**连续 2 次落子核对失败即拉黑**，改下引擎候选列表里的下一个点，杜绝"反复点同一个点"；任何一手核对成功即清空黑名单。
- **星阵（浏览器平台）取图从未生效**：截图函数读的是**类**属性而非运行中的配置**实例**，导致平台判断永远是默认值，走的是"找腾讯围棋窗口"分支，窗口取图 / 镜像设置实际都没生效。已改为显式传递实例。
- **窗口取图不再靠运气**：原来只在"截不到图"时才回落窗口取图；被弹窗遮挡时能截到图但**认不出棋盘**，就一直空转。现在"认不出棋盘"同样自动回落 `PrintWindow` 窗口取图（不受遮挡影响）。
- **日志噪音**：落子后等 2.5s 读帧时对手常常已经应手/提子，一帧内新增两手顺序无法确定，重放必然对不上 —— 这属于正常现象，旧版却**每手都刷两行**「历史不一致, 清空重来」。现在每局只在首次退化时提示一行说明，之后完全静默（清空兜底逻辑不变）。

### v1.0.2（2026-09-11）

- **修复（重要）**：长时间运行内存暴涨 —— 看板每 2 秒把**整份** KataGo 日志读进内存，而日志随对局不断变大（可达数百 MB），内存只涨不落，最终吃满内存。现改为**只读日志尾部**（上限 256KB），内存与日志大小无关：实测读 202MB 日志仅 +2MB（修复前读 73MB 就 +165MB）。整栈常驻内存约 **330MB**
- 新增 gtp 日志轮转（保留最新 6 个、目录上限 256MB），启动时与运行中定期清理
- **修复**：点击「启动 KataGo 预加载 / 执黑启动」会同步等待整个冷启动（最长 180 秒），浏览器请求挂死、看起来"点了没反应"；现改为后台执行并立即返回
- **修复**：停止 AI 后可能被后台启动线程重新拉起（孤儿进程）；进程快照过期时"停止"可能杀不掉新启动的 controller（AI 会继续下棋）—— 两者均已修复
- 内存优化：KataGo NN 缓存上限减半（`nnCacheSizePowerOfTwo = 19`）、搜索线程 16→8；看板 HTTP 服务改用守护线程
- 其它：引擎 stderr 缓冲队列加上限、启动器日志句柄泄漏修复
- 顺带：看板 HTTP 轮询响应从 214 秒降到 9 秒
